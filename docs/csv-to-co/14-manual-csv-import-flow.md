# 14 — Manual CSV Import Flow

## Status

Dokumen ini menetapkan rancangan **manual CSV import** untuk Proof of Concept, UAT, dan operational fallback. Jalur produksi utama masih dapat menggunakan REST API ketika source resmi siap.

## Keputusan Utama

Raw data dapat masuk melalui dua channel yang memakai processing core yang sama:

```text
Manual CSV Form ─┐
                 ├─> Inbound -> Batch -> RawLine/Transaction -> Validation -> Posting Preview
REST API ────────┘
```

Manual CSV tidak melakukan insert langsung ke entity IDO. Form memanggil method pada service IDO `SMKRSCPosIntegration` agar idempotency, validation, logging, transaction boundary, dan rollback tetap terkontrol.

## Form

```text
Form Name    : SMKRSCPosImportCenter
Display Name : RSC POS Import Center
Purpose      : Upload, validate, import, dan review file CSV POS
```

Form ini bersifat hybrid:

- primary collection: `SMKRSCPosInbounds`;
- imported-row collection: `SMKRSCPosRawLines`, difilter berdasarkan `BatchNum`;
- error/log collection: `SMKRSCPosProcessLogs`, difilter berdasarkan `BatchNum` atau `RequestId`;
- proses upload/import: method pada `SMKRSCPosIntegration`.

## Mekanisme Pemilihan File

### PoC yang Direkomendasikan

Gunakan document attachment standar Mongoose pada record inbound:

1. user membuat manual inbound request;
2. sistem menghasilkan `InboundId` dan `RequestId`;
3. user menekan **Browse / Attach CSV**;
4. form membuka Attached Documents untuk record inbound yang aktif;
5. user memilih file `.csv` dari komputer;
6. file di-upload dan di-attach ke record inbound;
7. user menekan **Validate File**;
8. service method membaca attachment, memvalidasi struktur, dan menampilkan hasil;
9. user menekan **Import to Staging**;
10. service method membuat batch dan raw lines secara transactional.

User tidak mengisi path server atau path lokal secara manual. File dipilih menggunakan browse dialog dan di-upload ke Mongoose.

### Enhancement Berikutnya

Bila diperlukan pengalaman satu tombol, form web dapat memakai custom upload user component yang langsung mengirim binary file ke service layer. Enhancement tersebut tidak dibutuhkan untuk PoC awal.

## Import Profile

### Minimal Profile v1

```text
Profile Code : POS_MINIMAL_V1
Delimiter    : comma (,)
Encoding     : UTF-8
Header Row   : required
Date Format  : yyyy-MM-dd
Decimal      : dot decimal; no thousands separator
```

Required columns, in this exact version:

```text
business_date,trans_num,pos_item_code,pos_qty,total_amt
```

Example:

```csv
business_date,trans_num,pos_item_code,pos_qty,total_amt
2026-07-23,TRX001,PIZZA001,2,200000
2026-07-23,TRX001,DRINK001,1,25000
2026-07-23,TRX002,PIZZA002,1,125000
```

`source_row_num` is generated by the importer and is not required in the CSV.

## Metadata Entered on the Form

The minimal CSV does not repeat integration metadata on every row. The form supplies:

```text
SourceSystem
OutletCode
ImportProfile
PayloadVersion
Optional SourceReference
Optional IdempotencyKey
```

The importer derives:

```text
PeriodStart = minimum business_date
PeriodEnd   = maximum business_date
TransCount  = distinct business_date + trans_num
RowCount    = number of non-header data rows
PayloadHash = SHA-256 of uploaded file, when supported
```

## Candidate Service Methods

### CreateManualInbound

```text
Success

```

### ValidateAttachedCsv

```text
Inputs:
InboundId
DocumentId or attachment reference
ProfileCode

Outputs:
Success
FileName
RowCount
ValidCount
ErrorCount
PeriodStart
PeriodEnd
TransCount
TotalAmt
Message
```

Validation does not create posting records. Row-level errors are written to process log or returned in a validation result set according to the implementation selected for the tenant.

### ImportAttachedCsv

```text
Inputs:
InboundId
DocumentId or attachment reference
ProfileCode
ForceFlag

Outputs:
Success
DuplicateFlag
BatchNum
RowCount
AcceptedCount
RejectedCount
TransCount
TotalAmt
Message
```

This method performs:

```text
1. Recheck inbound and attachment
2. Recheck idempotency and payload hash
3. Parse CSV
4. Validate header and data types
5. Create batch
6. Insert raw lines
7. Reconcile dates, rows, transaction count, and total
8. Update inbound result
9. Write process log
10. Commit
```

A critical failure rolls back the batch/raw-line insert. The inbound error record remains available for troubleshooting.

## Validation Rules

File-level:

- extension must be `.csv`;
- profile must be supported;
- header must match the profile;
- file must not be empty;
- encoding and delimiter must be accepted;
- duplicate/idempotency policy must pass;
- configurable maximum size and row count must not be exceeded.

Row-level:

- `business_date` must parse using `yyyy-MM-dd`;
- `trans_num` is required;
- `pos_item_code` is required;
- `pos_qty` must be numeric;
- `total_amt` must be numeric;
- blank trailing rows may be ignored;
- source row number is generated from the physical row order;
- item mapping may be validated during import or during `ValidateBatch`, depending on the selected processing mode.

## Validation Versus Import

```text
Validate File
= read and check the CSV; do not create the final batch/raw lines

Import to Staging
= parse again under a database transaction and create batch/raw lines

Validate Batch
= validate mappings and business rules after staging exists
```

The two-stage design prevents a malformed file from silently becoming an operational batch.

## Duplicate Handling

Duplicate checks use, in order:

```text
1. SourceSystem + IdempotencyKey, when supplied
2. SourceSystem + RequestId
3. Payload SHA-256, when supported
```

A duplicate file returns the existing request/batch reference and does not create a second batch.

## Manual CSV Versus API

| Concern | Manual CSV | REST API |
|---|---|---|
| Primary use | PoC, UAT, fallback | Production integration |
| Input | Uploaded CSV attachment | JSON request |
| User interaction | Form and browse dialog | System-to-system |
| Processing | Service IDO | Same service IDO/core logic |
| Staging result | Same tables | Same tables |
| Validation | Same rules | Same rules |
| Idempotency | File/request based | Request/idempotency key based |

Manual import is therefore not throwaway functionality. It is also useful for troubleshooting, controlled reprocessing, migration, and operational fallback.

## Tenant Verification Items

Before implementation, verify:

- how document attachment bytes are read from an IDO method in the target tenant;
- allowed file types and file-size limits;
- document retention and cleanup behavior;
- whether extension class or stored procedure is the supported parser implementation;
- availability of CSV parsing libraries in the approved extension environment;
- authorization needed for attaching and reading documents;
- web-client and Windows-client behavior;
- background processing requirement for large files.
