# SMK069 POS CSV Test Console

## Identity

```text
Display Caption      : SMK POS CSV TEST CONSOLE
Primary Collection   : ue_SMK069PosCsvBatch
Secondary Collection : ue_SMK069PosCsvUpload
Relation              : BatchId = FP(BatchId)
Purpose               : Functional/UAT harness for POS Contract V2
```

The console mirrors the production Receive contract. It parses CSV rows and sends
the same canonical V2 business fields to `SMK069ReceivePosSalesJsonSp`.

It does **not** create Customer Orders directly.

## POS Contract V2 CSV

Required CSV columns:

```text
custnum
order_date
cust_po
whse
coline
item
qty_ordered
u_m
```

Recommended column order:

```csv
custnum,order_date,cust_po,whse,coline,item,qty_ordered,u_m
```

Example:

```csv
custnum,order_date,cust_po,whse,coline,item,qty_ordered,u_m
C000001,2026-08-06,POS08270003,MAIN,1,AA00032,1,CTN
C000001,2026-08-06,POS08270003,MAIN,2,AA00032,2,CTN
```

### Fields no longer supplied by CSV/POS

```text
conum       -> generated by Receive as R + YYMM + 5-digit running number
unit_price  -> resolved by Receive from itemcustprice_mst
```

Legacy physical columns may remain on the CSV-detail table for compatibility,
but the V2 parser/wrapper does not require or forward them.

## Required schema/IDO property

`dbo.ue_SMK069_pos_csv_upload_mst` must contain:

```text
cust_po CustPOType / nvarchar(25)
```

Secondary IDO `ue_SMK069PosCsvUpload` must expose:

```text
Property : CustPo
Column   : cust_po
Type     : String
Length   : 25
```

Apply:

```text
database/patches/2026-08-27-smk069-pos-contract-v2-csv-console.sql
```

then refresh/update IDO metadata.

## Main flow

```text
New Batch
-> Upload CSV
-> Save binary
-> SMK069ImportCsvFileSp
-> parsed detail rows
-> Import & Validate
-> SMK069RunCsvTestBatchSp
-> V2 JSON (cust_po/whse/u_m; no conum/unit_price)
-> SMK069ReceivePosSalesJsonSp
-> validation + pricing + co_num generation
-> temp process_status = V
```

Process/Reprocess remains separate:

```text
SMK API SALES ERROR PROCESSING
-> SMK069ProcessCustomerOrderSp
-> co_mst type B
-> coitem_mst
-> co_bln_mst
-> temp process_status = P
```

## Upload event target

```text
0  Binary Value Action -> CsvFile
10 Collection Save -> primary
20 Call SMK069ImportCsvFileSp
30 Collection Refresh -> primary
40 Collection Refresh -> secondary
```

File Name remains hidden. Parsed rows, counts and Result Message are the useful
operational indicators.

## Parser rules V2

Basic CSV/parser validation:

```text
custnum       required, <= 7
order_date    required, valid date
cust_po       required, <= 25
whse          required, <= 8
coline        required, integer > 0
item          required, <= 30
qty_ordered   required, numeric > 0
u_m           required
```

Business/master validation remains in Receive:

```text
customer
item
warehouse
terms
U/M item/base or item-specific conversion
customer/item effective price
duplicate line
header consistency by SiteRef + cust_po
existing cust_po/order
```


Hide/remove from the parsed CSV grid:

```text
Source/CSV conum
CSV Unit Price
```

because both values are now server-derived later in Receive.

Generated `co_num` and resolved `unit_price` are viewed from inbound/temp after
Import & Validate.

## Status meanings

### Detail upload status

| Value | Meaning |
|---|---|
| N | Parsed and ready for Import & Validate |
| E | CSV format/basic parser error |
| S | Import & Validate completed successfully |

### Batch status

| Value | Meaning |
|---|---|
| D | Draft/parsed and ready |
| R | Import & Validate running |
| E | Parse/receive/validation error |
| C | Receive/validation completed |

`C` does not mean the Blanket Customer Order has already been created.
