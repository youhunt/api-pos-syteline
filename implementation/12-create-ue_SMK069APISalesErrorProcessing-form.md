## Purpose

The form is the controlled boundary between validated temp data and the standard SyteLine Blanket Customer Order tables.

```text
Receive
-> temp V
-> Error Processing
-> Process/Reprocess by generated co_num
-> co_mst type B
-> coitem_mst
-> co_bln_mst
-> temp P
```

Invalid Receive rows remain in inbound and do not enter this form's temp collection.

## Number semantics V2

```text

co_num  = final SyteLine Customer Order number generated by Receive
```

Confirmed UAT:

```text
cust_po = POS08270002
co_num  = R260822003
```

## Process/Reprocess method

Procedure:

```text
dbo.SMK069ProcessCustomerOrderSp
```

Parameters:

```text
SiteRef       = current SiteRef
SourceCoNum   = current co_num
CustSeq       = 0
ProcessedBy   = USERNAME()
CreatedCoNum  = output
Success       = output
Infobar       = output
```

The parameter name `SourceCoNum` is retained for compatibility, but its V2 value is the generated staging `co_num`.

One call processes all rows with the same:

```text
SiteRef + co_num
```

## Form protection

This form must not be used to create or remove integration staging rows manually.

Required standard-operation settings:

```text
New/Create = disabled
Copy       = disabled
Delete     = disabled
```

System-maintained fields remain read-only. Processed rows must remain available for audit/traceability.

## Preview/filter guidance

The old meaning of `co_num` as a POS source number is obsolete.

Recommended filters:

```text
CO Number   -> co_num (generated SyteLine order)
Customer PO -> cust_po
Order Date  -> order_date
```

Do not load all rows when all filter criteria are blank.
